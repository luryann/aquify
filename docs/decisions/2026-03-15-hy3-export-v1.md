# Decision: HY3 Export v1 Scope

**Date:** 2026-03-15
**Status:** Locked
**Deciders:** Engineering, Product

---

## Context

HY3 is the proprietary container format used by Hy-Tek Meet Manager. It is a ZIP archive containing `.sd3` or `.cl2` inner payload files along with metadata. The DARE platform already supports **importing** HY3 files (STEP 10), treating the container as a ZIP and routing the inner SD3 or CL2 payload to the appropriate parser.

The question is whether v1 should also support **exporting** in HY3 format.

---

## Decision

**HY3 export is explicitly out of scope for v1.**

DARE v1 exports meet entries as Standard SD3 and Extended SD3 only. HY3 export is deferred to v1.1 or later.

---

## Rationale

1. **SD3 sufficiency:** Standard and Extended SD3 files are accepted by Hy-Tek Meet Manager directly. The HY3 container format adds no additional data — it is only a ZIP wrapper around SD3 content with a different file extension. Coach and admin users at member clubs can rename a valid `.sd3` file with a `.hy3` extension as a workaround if needed.

2. **Spec opacity:** HY3 is a proprietary format with no public specification. While its container structure is well-understood (ZIP + inner SD3/CL2 payload), the exact metadata files expected by different Meet Manager versions are undocumented. Attempting to produce a correctly-structured HY3 without verified samples risks generating files that are rejected by target software — a worse outcome than shipping SD3 only.

3. **Scope risk:** Adding HY3 export requires: (a) producing correctly-structured ZIP archives, (b) injecting any expected metadata files (`hy3info.txt`, version manifest, etc.), and (c) end-to-end verification against actual Meet Manager software. This scope is disproportionate to the benefit when SD3 works.

4. **Customer validation:** No swim club stakeholder has specifically required HY3 export as a launch blocker. SD3 export meets the interoperability requirement documented in the Developer Handoff Master Document (section 1.1, F-007).

---

## API Behavior

The export endpoint (`POST /api/v1/meets/{meetID}/exports`) will return HTTP 400 if `export_type` is set to `"hy3"` or any HY3 variant, with error code `invalid_export_type` and a message directing users to use `standard_sd3` or `extended_sd3`.

```json
{
  "error": {
    "code": "invalid_export_type",
    "message": "HY3 export is not supported in v1. Use standard_sd3 or extended_sd3."
  }
}
```

---

## Consequences

- SD3 files exported by DARE can be imported directly into Hy-Tek Meet Manager without manual conversion.
- Users who specifically require a `.hy3` extension can rename the exported `.sd3` file. This is documented in the user guide.
- HY3 export will be scoped and re-evaluated for v1.1 once verified sample files and Meet Manager acceptance criteria are available.
- The existing HY3 import path (STEP 10) is unaffected.
